<p class="lead">This blog's been quiet for about six weeks. Going forward I'm aiming to post weekly: what I built, what broke, and what's happening in the AI tools I use daily that's actually worth your time. If a week's quiet, I'll just say that instead of padding it out.</p>

<p>This week's biggest thing was a page I had to pull.</p>

<h2>I pulled my "Google Maps Growth" page</h2>

<p>I had a page on this site promising a managed Google Business Profile growth service. I wrote that page ahead of actually building and testing the thing, which is backwards, and I noticed it before anyone signed up for something I couldn't yet back up.</p>

<p>So it's down. The old URL now redirects to <a href="/visibility-audit">a local-visibility audit</a> I'm building to replace it, pulling real data from DataForSEO instead of a page that just said the right words. Along the way I found three places where I'd guessed at DataForSEO's response schema instead of reading their actual docs, and all three guesses were wrong. Those are fixed now. But fixing three known bugs isn't the same as the tool being done: I haven't run it end-to-end against enough real businesses yet to call it tested, so I'm not calling it that. It's further along than the page it replaced, and that's the honest claim for now.</p>

<p><em>Update (October 1): I pulled the visibility audit too, for the same reason. Both URLs now go to the homepage.</em></p>

<p>The one thing I am sure of: this tool is read-only against DataForSEO. There's no version of it, tested or not, that touches anyone's actual Google Business Profile without me looking at it first.</p>

<h2>A merge gate that catches some of my own review</h2>

<p>The other piece of infrastructure that went live this week: a chunk of my code review now runs in CI instead of living entirely in my head.</p>

<p>The shape of it: an agent opens a pull request. A second, independent review runs against it, separate context from whoever wrote the code, so it isn't just checking its own work. If that review comes back clean and the tests pass, the PR is meant to merge without me clicking anything.</p>

<p>Where it stops matters more than where it doesn't: anything touching money, production data, outbound messages to clients, or a handful of paths I've explicitly flagged still needs my sign-off on the PR itself before it merges. Everything else has to clear the same bar a human reviewer would hold it to. It's not fully proven yet either: it's a few days old, and I'm watching it.</p>

<p><em>Correction (October 2026): the auto-merge step described here never merged anything. It wasn't switched on in this repo until September 24, and from then a bug kept it from ever completing, so every approved PR still needed my click. The bug was found and a fix merged on October 2.</em></p>

<p>Same principle as the pipeline I wrote about for <a href="/blog/how-my-beta-testers-texts-become-app-updates">a salon client's beta loop</a> back in August: keep a human between the agent and anything that isn't small and recoverable.</p>

<h2>What broke: the whole dev box</h2>

<p>Build in public means the failures count too. My dev machine went down hard this week: not a service, the whole WSL2 VM. Turned out to be memory exhaustion: something ran the guest out of RAM until the kernel gave up, taking every agent session and cron job with it.</p>

<p>I looked at the usual fixes (systemd-oomd, earlyoom) and neither fit how this VM is actually set up. What's running now instead is a small watchdog that scores processes by memory use and kills the worst offender before the kernel has to. It's boring, and I haven't stress-tested it hard enough to call it solved, but it's watching the box now instead of nothing.</p>

<h2>What's worth your attention this week</h2>

<p>Part of the point of this weekly post is the tools I'm actually using, not just what I'm building. Three things this week are worth knowing if you build with agents at all:</p>

<ul>
<li><strong>Cloudflare started blocking AI agent traffic by default</strong> on pages that run ads, as of September 15. Their definition of "agent" is broad: anything acting in real time on someone's behalf, including browser-use agents. If you've got an agent that fetches or acts on the open web, worth checking your own traffic against this before something quietly starts failing.</li>
<li><strong>Cloudflare also shipped temporary accounts for AI agents</strong>: <code>wrangler deploy --temporary</code> puts a Worker live with no signup, and a human has 60 minutes to claim it permanently through a browser link. Useful pattern if you want an agent standing up infrastructure without handing it permanent credentials.</li>
<li><strong>Claude Code's September release</strong> extended Cowork to web and mobile, with sessions saved and synced across devices instead of living in one terminal window. I'm writing this post in Claude Code right now, so this isn't abstract for me: it's the tool doing the work.</li>
</ul>

<p>I'm also a few weeks into trying out <strong>God's Eye View</strong>, an open-source live-map project, on an isolated install on this box. Still auditing it, nothing to report yet. I'll write about it once I've actually put it through its paces.</p>

<h2>Next week</h2>

<p>Same format: what shipped, what broke, what I'm still testing. If you want an agent you message on Telegram that runs your recurring work, that's what I set up as <a href="/agent-system">an agent of your own</a>. Otherwise, see you next week.</p>
