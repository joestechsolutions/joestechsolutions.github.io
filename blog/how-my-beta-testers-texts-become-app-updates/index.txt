<div class="grid gap-4 sm:grid-cols-2 lg:grid-cols-3 my-6">
  <div class="p-6 bg-surface-raised rounded-lg border border-line">
    <h3 class="m-0 mb-2 heading-3">1. Code-only bug fix</h3>
    <p class="m-0 body-s">The agent writes a <strong>failing test first</strong>, then the fix. All tests + CI must pass, and an automated code review must come back clean. Then it ships as an over-the-air update without waiting on me. I get the update-group ID and a one-line rollback command.</p>
  </div>
  <div class="p-6 bg-surface-raised rounded-lg border border-line">
    <h3 class="m-0 mb-2 heading-3">2. New feature</h3>
    <p class="m-0 body-s">The agent builds it and opens a <strong>pull request</strong>. It stops there. Merge is mine: one-tap approve, then it ships the same OTA path.</p>
  </div>
  <div class="p-6 bg-surface-raised rounded-lg border border-line">
    <h3 class="m-0 mb-2 heading-3">3. Native / database change</h3>
    <p class="m-0 body-s">Anything touching native modules or the schema <strong>always stops at me</strong>, then goes out as a new TestFlight build she installs once. Mismatched JavaScript against an old native binary crashes the app, so this lane never ships over the air.</p>
  </div>
</div>

<p>The three lanes are a safety design, not a limitation. Code-only fixes ship without me because a failing test first, green CI and a clean code review are a real gate. Anything that changes the product's shape or its foundations waits for a human.</p>

<h2 class="heading-1">Two views of the same event</h2>
<p><strong>What she sees:</strong> she texts about the missing volumes. The bot says "Got it."</p>
<p><strong>What actually happened:</strong> her message was triaged into a labeled, deduplicated GitHub issue.</p>
<p>That gap, between what she experiences and what the machinery does, is the entire product. She gets a fast line to her developer. I get a paper trail with a test suite.</p>

<h2 class="heading-1">The outage that put it under a watchdog</h2>
<p>Build in public means the failure ships too, so here it is. In early August the whole loop went dark for four days, and nobody noticed, which is the worst kind of outage.</p>
<p>The agent session lived in a terminal window on my machine. A Linux restart killed it silently. And here's the brutal detail: Telegram discards undelivered bot messages after about 24 hours, so everything she texted during those days is simply gone. No error, no queue, no replay.</p>
<p>The fix was to stop treating the agent like a process I start and start treating it like a service the machine owns:</p>
<ul>
  <li>On boot, a watchdog timer starts the agent automatically, and health-checks it on a schedule, replacing it if it's half-dead.</li>
  <li>It refuses to run in the mode that once leaked permission prompts into her chat: she saw approval buttons meant for me. Fixed at the source.</li>
</ul>

<p>The lesson generalizes: an autonomous agent is only as reliable as its supervisor. The interesting engineering isn't the AI drafting the fix: it's the boring systemd timer making sure the AI is still listening.</p>

<h2 class="heading-1">Guardrails that stay on</h2>
<p><strong>Happens without asking:</strong> replies to her, GitHub issues generated from her feedback, and code-only bug fixes that pass the tests, CI and the code review.</p>
<p><strong>Always stops at me:</strong> feature merges, database schema, auth, native modules, App Store builds, and anything her messages <em>instruct</em>. That last one matters more than it looks: her texts are treated as feedback data, never as commands. An agent that obeys instructions found inside user input is an agent waiting to be hijacked. Mine reads "delete all my competitors' reviews" as a bug report about something weird in her inbox, not a task.</p>
<p>And every OTA update has a one-line rollback: republish the previous known-good update group to the production channel. Autonomy without rollback isn't autonomy: it's gambling.</p>

<h2 class="heading-1">Why I'm showing you this</h2>
<p>This is the pattern I offer as <a href="/fixbot">FixBot</a>: messages become tracked issues, and human gates sit exactly where the blast radius demands them. The salon's app is where I run it first, on a real client's app, in public. If it doesn't survive her salon, it doesn't ship to you.</p>
